## 三、现场演示（110 秒，5 步，每步一句话）

**准备**：先打开 `examples\demo-adder.mlc`（一位全加器 + 时钟计数器 + 子电路），窗口最大化。

### 第 1 步（20 秒）看整体布局
> "左边是元件库和工具，左下是资源管理器和属性表，中间是栅格画布，底部状态栏实时显示坐标、缩放和仿真节拍。"

**动作**：鼠标在画布上移动，指一下状态栏的 `X/Y` 在变。

### 第 2 步（25 秒）实时仿真 —— 这是核心卖点
> "现在直接点'查探'工具，点一下输入引脚 A。"

**动作**：点 A → A 变亮、导线变色、S/Cout 跟着变。
> "导线颜色就是电平：亮绿=1，暗绿=0，蓝色=悬空，红色=冲突。整个全加器是实时算出来的，不是我画的静态图。"

**再点** B、Cin 各一次，让 Cout 变 1（进位出现）。

### 第 3 步（20 秒）时钟驱动时序电路
> "`Ctrl+E` 启动仿真。"

**动作**：按 `Ctrl+E`，指一下右下角 4 位数码管在走字、状态栏"节拍"在涨。
> "时钟每翻转两次，计数器加一，数码管实时显示。这就是时序电路。"

**再次 `Ctrl+E` 暂停**（很重要，别让它一直跑）。

### 第 4 步（25 秒）层次化设计
> "双击这个'反相器'方块。"

**动作**：双击子电路 → 进入内部，看到输入引脚、非门、输出引脚。
> "任何一张电路图都能当元件用，出现在左边的'项目'库里。这是 Logisim 的核心思想，我实现了完整的层次展开仿真。"

**点资源管理器里的 `main`** 回到主电路。

### 第 5 步（20 秒）编辑能力
> "最后看编辑：选中一个门，按 R 旋转；左下角属性表可以改位宽。"

**动作**：点一个与门 → 按 `R` → 属性表里把"数据位宽"改成 4 → 门变宽、引脚标签变。
> "改完立即重新仿真，不用重启。"

### （可选，时间够再加 15 秒）
**项目 → 组合逻辑真值表** → 自动跑出 3 输入 2 输出的完整真值表。
> "这是我额外做的分析工具，一键把电路跑成真值表。"

## 四、技术亮点（50 秒，挑 3 个讲，别念代码）

### 亮点 1：仿真内核不是查表，是真正的网络求解
> "把导线、引脚、隧道用**并查集**归并成'网络'，再对元件做**迭代求值直到收敛**。
> 所以：T 型搭接自动连通、十字交叉自动不连通、组合逻辑环会检测出振荡并在状态栏报警。"

### 亮点 2：时序元件是真正的边沿触发
> "我没有简单地把输入算完就写输出。求值阶段只计算'下一状态'和'时钟端当前电平'，
> 时钟节拍到来时才检测**上升沿**并锁存。所以 D 触发器、寄存器、计数器、RAM 的行为是对的。"

### 亮点 3：一套渲染代码，三处复用
> "元件的图形全部是**矢量绘制**，没有任何图片资源。同一段绘制代码同时用于：
> 画布、左侧元件库的图标、PNG 导出。所以画布上什么样，库里图标就是什么样。"

## 五、需要改进的地方（50 秒，分级说，显得有规划）

### 已完成但还需接线（P0，最该说，体现诚信）
- **运行时动态元件库**：数据模型、绘制、仿真、序列化都已写好并通过编译，
  但工具箱入口和菜单入口还**没接上**，所以界面上暂时看不到。接线后即可"不重编译、随时新增元件"。

### 功能短板（P1）
| 不足 | 影响 | 打算 |
|---|---|---|
| 单一时钟域 | 复杂时序电路受限 | 加元件级时钟属性 |
| 无传播延迟 | 只能做理想零延迟仿真 | 加元件延迟模型 |
| 组合环只报"振荡" | 不做时序分析 | 接入迭代次数可视化 |
| 撤销是整份快照 | 大电路内存与速度 | 改为命令模式/差异补丁 |
| 每次改动全量重建网络 | 大电路仿真帧率 | 增量重建 |

### 体验短板（P2）
- 无线框选搜索框、无最近文件、无多标签页
- 属性编辑靠弹窗，不是内联编辑
- 只有 PNG 导出，不能打印/导出网表
- 界面文案硬编码中文，没有做 i18n
- 无 UI 自动化测试（只有内核自测）

## 六、典型困难（3 个故事，40 秒，这是最能加分的部分）

### 困难 1：仿真"看着在跑，其实根本没动"
> 现象：点开始仿真，界面没反应，也没报错。
> 排查：发现 `wxTimer` 没有 `SetOwner(this)`，定时器**从来没触发过**。
> 更麻烦的是"看不出来"——窗口在后台时 Windows 不重绘，抓到的画面是**缓存的旧画面**，
> 看起来像"跑了但卡住"。
> 解法：给程序加了一个 `--export` 无界面导出模式，把"功能是否正确"变成
> "仿真 13 个节拍后计数器是不是 7"这种**可断言的数字**。一测就现形。

### 困难 2：迭代求值和"边沿触发"天生冲突
> 问题：组合逻辑用"反复迭代直到稳定"来求解，但这样 D 触发器的 D 会**立刻**传到 Q，
> 变成电平触发，寄存器全错。
> 解法：拆成两阶段——求值阶段只算"下一状态"和"时钟端电平"，
> 节拍到来时再检测上升沿并锁存。同时给迭代设 120 轮上限，超了就在状态栏报"检测到振荡"。

### 困难 3：连线拓扑 —— 十字交叉不能连、T 型搭接必须连
> 问题：如果"坐标相同就连"，十字交叉处会短接，电路全错。
> 解法：只对"**落在别的线段上的点**"做归并。
> 十字交叉处**没有任何一条导线的顶点**，所以天然不连通；而 T 型搭接的端点确实落在别人线段上，所以连通。
> 配合网格哈希索引把 O(n²) 降到近似 O(n)。

### 困难 4（一句话带过）：中文与构建环境
> MSVC 默认 GBK 源文件编码，中文全乱码 → 编译加 `/utf-8` 且全部改用 `wxT()` 宽字面量；
> 本机 wxWidgets **只编译了 Debug 静态库**，Release 直接链接失败，库名还是 `ud` 和 `d` 混着的
> （`wxbase32ud.lib` 但 `wxpngd.lib`），这些都写进了 README 避免下次踩。

## 八、可能被问到的问题（提前准备）

| 提问 | 回答要点 |
|---|---|
| 和 Logisim 比有什么不同？ | 同类的交互，但内核自己实现；额外有真值表生成、PNG 导出、无界面批量导出；代码量小、结构清晰，便于二次开发 |
| 仿真精度如何？ | 理想零延迟、事件收敛模型；组合环用迭代上限检测振荡；**没有传播延迟**（列为改进项） |
| 支持多驱动吗？ | 支持，冲突时该网络标红（冲突态），三态门可以正确实现总线 |
| 位宽上限？ | 32 位；RAM/ROM 最大 1024 项（地址位宽 ≤10） |
| 怎么保证正确性？ | `tools/SimTest` 36 项断言：门真值表、全加器 8 种组合、时钟计数器节拍序列、分线器位段、隧道连通、D 触发器边沿、子电路层次、存盘往返 |
| 代码量/工作量？ | 6656 行 / 21 文件；另有 292 行自测程序、2 份文档 |
| 最难的地方？ | 见第六节，首推"边沿触发与迭代求值的冲突" |

# 动态元件库 —— 接入契约（自己写之前先读这个）

目标：**运行时**新增元件（不改代码、不重编译），并且和现有代码**无缝**：
能放置、能连线、能仿真、能存盘、能撤销、能撤销后重做、能出现在工具面板里、图标自动生成。

---

## 0. 先做一个决策：动态元件怎么表示？

`Component::type` 是**编译期枚举**，指向 `g_meta[]` 那张静态表。动态元件不在表里，所以必须先给它一个"落点"。三种做法：

| 方案 | 做法 | 存盘 | 撤销 | 删定义 | 评价 |
|---|---|---|---|---|---|
| **A 外壳类型 + 索引**（推荐） | 新增一个内置类型 `CT_My`，再加字段 `int defIndex` 指向 `Document::myDefs[]` | 元件存索引，定义单独存 | 随文档快照自动 | 需重映射索引 | 改动最小，和现有架构同构 |
| B 定义内嵌到元件 | `Component` 里直接放一个 struct | 每个元件重复存一份 | 自动 | 无此问题 | 存盘膨胀，同一元件改一次要改所有实例 |
| C App 级全局注册表 | 注册表放 `wxApp` / 单例 | 元件存 id | **不自动** | 悬空引用 | 多文档、撤销会错乱，不推荐 |

**选 A。** 下面全部按 A 写。

---

## 1. 最重要的一条：定义必须放在 `Document` 里，不能放全局

原因（这四条决定了"完美融入"）：

1. **撤销/重做 = 整个 `Document` 的序列化快照**
   `MainFrame::PushUndo()` 存的是 `m_doc.Serialize()`，`Undo()` 用 `Deserialize()` 整个换掉。
   定义如果不在 `Document` 里，撤销元件时定义不会跟着回退 → 元件指向一个"未来"的定义。
2. **存盘** = `Document::Serialize()`，天然带上定义。
3. **仿真缓存** = `Document::version`。只有 `Touch()` 变 version，仿真器才重建网络。
4. **多文档隔离**：将来支持多标签页时不会互相污染。

## 3. 不变式（这几条最容易踩，全是"看着能跑其实全错"）

### 3.1 枚举编号 = 文件格式
`Component::type` 直接写进 `.mlc`。所以：
- 新类型**只能追加**在 `CT_COUNT` 之前，已有编号一个都不能变；
- 新字段必须**有默认值**（`cdef` 默认 `-1`），这样老文件读不到新字段也不会错。

### 3.2 `Pins()` 的返回顺序 = 仿真里的引脚编号
这是最隐蔽的一条。`Simulator::Evaluate()` 里：

```cpp
h.In(0)    // 第 0 个“输入引脚” = Pins() 里第 0 个 isInput==true 的项
h.Out(0)   // 第 0 个“输出引脚” = Pins() 里第 0 个 isInput==false 的项
```

所以 **`Pins()` 必须按定义里固定的顺序返回**，不能在返回前排序。你一旦"为了好看"按 y 排一下序，仿真接线全错位。

### 3.3 `Size()` / `Pins()` 是 **const**，不能在里面改文档
而且**定义找不到时必须给安全值**（我给的是 60×60 和空引脚列表）。否则：文件里引用了已删除的定义 → 绘制/命中测试崩溃。

### 3.4 不要长期持有 `const MyDef*`
`myDefs` 是 `std::vector`，`push_back` 会 realloc；打开文件/撤销会整体替换。
**每次用的时候现查**（`doc->FindMyDef(c.myDef)`），或者干脆只存索引。

### 3.5 改定义之后必须 `Touch()`
仿真器只在 `doc->version` 变化时重建网络：

```cpp
if (m_dirty || m_cachedVersion != m_doc->version) Rebuild();
```

改了引脚位置但没 `Touch()` → 导线还连在**旧坐标**上，看着对、仿真错。

### 3.6 撤销前后指针全失效
`Undo()` → `Deserialize()` → `circuits` / `customDefs` 整体重建。
任何界面上缓存的 `Component*`（比如属性面板里的 `m_cur`）都必须在 `RefreshAll()` 里被重置。现有代码用 **id** 而不是指针就是这个原因（`SidePanel::m_curCompId`）。

### 3.7 `GetAttrDefs(const Component&)` 拿不到 `Document`
这是现有代码的一个既有限制。如果你的动态元件有"依赖定义"的属性（比如逻辑模板下拉框），有两个办法：
- 加一个重载 `GetAttrDefs(const Component&, const Document*)`，`SidePanel` 改调新重载；
- 或者让属性保持与定义无关（只暴露位宽/标签/朝向）。**建议后者**，改动最小。

## 4. 数据流（从你的定义到跑起来）

```
你的定义 MyDef
   │  存在 Document::myDefs[]
   ▼
放置元件 → Component{ type=CT_My, myDef=i }
   │
   ├─► Document::Size(c)      → 外形尺寸 ─────┐
   ├─► Document::Pins(c)      → 引脚表 ───────┤
   │                                          ├─► Renderer::DrawComponent()  画布/工具箱图标/PNG导出
   │                                          └─► Simulator::Evaluate()      仿真
   ├─► ToolBoxPanel::BuildToolGrid()  → “自定义”库按钮（图标也是上面那个函数生成的）
   └─► Document::Serialize()          → .mlc 文本（定义块 + 元件里的索引）
```

**注意**：工具箱图标是 `Renderer::MakeToolBitmap()` → 内部调 `DrawComponent()`。
所以**你只要把符号画对，库里的图标就自动是对的**，不用另做图。

## 5. 骨架代码（照抄改）

### 5.1 数据模型（`LogicModel.h`，放在 `struct Component` 之前）

```cpp
enum MyPrimKind { MP_POLY = 0, MP_RECT, MP_CIRCLE, MP_TEXT };

struct MyPrim {
    int  kind = MP_POLY;
    bool fill = false;
    std::vector<wxPoint> pts;   // 局部坐标
    wxString text;
};

struct MyPin {
    wxPoint pos;
    bool    isInput = true;
    int     bits = 1;
    wxString name;
};

struct MyDef {
    wxString name = wxT("我的元件");
    int w = 60, h = 60;         // 局部坐标下的外形
    int bits = 1;
    int logic = 0;              // 你的逻辑模板编号
    std::vector<MyPin> pins;    // ★ 顺序即引脚编号，不要排序
    std::vector<MyPrim> prims;
};
```

`Component` 里加：

```cpp
int myDef = -1;                 // 指向 Document::myDefs 的下标
```

`Document` 里加：

```cpp
std::vector<MyDef> myDefs;
const MyDef* FindMyDef(int i) const {
    if (i < 0 || i >= (int)myDefs.size()) return nullptr;   // ★ 必须容错
    return &myDefs[i];
}
int  AddMyDef(const MyDef& d);      // push_back + Touch()
bool RemoveMyDef(int i);            // erase + 重映射索引 + Touch()
```

删定义时的重映射（照抄，别省）：

```cpp
bool Document::RemoveMyDef(int idx)
{
    if (idx < 0 || idx >= (int)myDefs.size()) return false;
    myDefs.erase(myDefs.begin() + idx);
    for (auto& cir : circuits)
        for (auto& c : cir.comps) {
            if (c.type != CT_My) continue;
            if (c.myDef == idx)      c.myDef = -1;   // 变成“定义已删除”的占位
            else if (c.myDef > idx) --c.myDef;
        }
    Touch();                                     // ★ 不 Touch 仿真不重建
    return true;
}
```

### 5.2 尺寸与引脚（`LogicModel.cpp`）

```cpp
// Document::Size()
case CT_My: {
    const MyDef* d = FindMyDef(c.myDef);
    if (d) return wxSize(d->w < 20 ? 20 : d->w, d->h < 20 ? 20 : d->h);
    return wxSize(60, 60);                       // ★ 容错
}

// Document::Pins()
case CT_My: {
    const MyDef* d = FindMyDef(c.myDef);
    if (d) {
        for (const auto& p : d->pins) {           // ★ 按存储顺序，禁止排序
            PinInfo pi;
            pi.pos     = p.pos;
            pi.isInput = p.isInput;
            pi.bits    = (p.bits > 0) ? p.bits : ClampInt(c.bits, 1, MAX_BITS);
            pi.name    = p.name;
            v.push_back(pi);
        }
    }
    break; }
```

### 5.3 画符号（`Renderer.cpp`，`DrawComponent` 的 switch 里）

```cpp
case CT_My: {
    const MyDef* d = doc ? doc->FindMyDef(c.myDef) : nullptr;
    // 底色
    Poly box; AddRect(box, 0, 0, w, h);
    dc.SetBrush(wxBrush(wxColour(252, 252, 248)));
    DrawPolyWorld(dc, c, sz, box, true);
    dc.SetPen(wxPen(ColOutline(), 2));
    DrawPolyWorld(dc, c, sz, box, false);
    if (!d) break;                                // 定义缺失：画个空框就行
    // 图元
    for (const auto& p : d->prims) {
        switch (p.kind) {
        case MP_POLY:  if (p.pts.size() >= 2) DrawPolyWorld(dc, c, sz, p.pts, p.fill); break;
        case MP_RECT:  { int x0=..., y0=..., x1=..., y1=...; Poly r; AddRect(r,x0,y0,x1-x0,y1-y0);
                         DrawPolyWorld(dc, c, sz, r, p.fill); } break;
        case MP_CIRCLE:{ wxPoint ctr = LocalToWorld(c, sz, p.pts[0]);
                         dc.DrawCircle(ctr, radius); } break;
        case MP_TEXT:  TextW(dc, c, sz, p.pts[0].x, p.pts[0].y, p.text); break;
        }
    }
    break; }
```

现成的绘图原语（都在 `Renderer.cpp` 匿名命名空间里）：
`DrawPolyWorld(dc,c,sz,Poly,fill)`、`LineW`、`CircleW`、`TextW`、`AddRect`、`AddArc`、`AddQuad`。
**所有坐标都用局部坐标系**，`LocalToWorld` 会自动处理朝向（旋转），你不用自己算。

另外：末尾那段"统一画引脚圆点"的代码要跳过你的类型，否则重复画：
```cpp
if (!iconMode && sim && c.type != CT_My) { ... }
```

### 5.4 仿真（`Simulator.cpp`，`Evaluate` 的 switch 里）

```cpp
case CT_My: {
    const MyDef* d = m_doc ? m_doc->FindMyDef(c.myDef) : nullptr;
    if (!d) { for (int i = 0; i < (int)fc.outIdx.size(); ++i) h.Out(i, ErrV()); break; }
    // h.In(k) / h.Out(k) 的 k 与 Pins() 的顺序严格对应
    PinValue a = h.In(0);
    if (a.state != 1) { h.Out(0, ErrV()); break; }
    h.Out(0, OkV(a.bits & mask));
    break; }
```

可用的辅助：`OkV(v)`、`ErrV()`（冲突/错误，红线）、`FloatV()`（悬空，蓝线）、`mask`、`ClampInt`。
**"输出悬空"的做法是"什么都不写"**——不写驱动，网络没有别的驱动源就自动是悬空态。

### 5.5 存盘（`LogicModel.cpp`）

`Serialize()` 里，在电路之前写定义块：

```
CUSTOM name="我的元件" w=60 h=60 logic=0 bits=1
  PRIM kind=1 fill=0 pts="0,0;60,60" text=""
  PIN  name="IN" in=1 bits=1 x=0 y=30
ENDCUSTOM
```

元件行加一个字段（老文件读不到就用默认 `-1`）：

```
COMP id=5 type=34 ... mydef=0 ...
```

`Deserialize()` 里用和 `CUSTOM` 一样的手法：`StartsWith("CUSTOM")` 起一个块，`PRIM`/`PIN` 往里塞，`ENDCUSTOM` 结束；循环结束后 `myDefs = newDefs;`。
（细节可参考现有 `Document::Deserialize` 里 `CUSTOM/PRIM/PIN` 三段，`LogicModel.cpp:1056` 附近。）

### 5.6 进元件库（`ToolBoxPanel.cpp`）

`LibId` 里加 `LIB_MY`（在 `LIB_COUNT` 之前），`LibName()` 给中文名，然后 `BuildToolGrid()` 里特判：


## 6. 自测清单（按顺序过一遍，每条都能验出不同的错）

| 测什么 | 怎么测 | 出错说明 |
|---|---|---|
| 放置 | 工具箱点按钮 → 画布点击 | ⑭没写，放出来是 0 号定义 |
| 连线 | 引脚能被布线工具吸附 | ⑥引脚坐标错 |
| 仿真 | 输入不同组合看输出 | ⑥顺序错 / ⑩没写 |
| 存盘 | 保存 → 重开 | ⑪没写 |
| 撤销 | 改定义 → 撤销 → 再重做 | 定义没放在 Document 里（第 1 节） |
| 删定义 | 删掉定义后看老元件 | ⑮没重映射 / ⑤⑥没容错 → **崩溃** |
| 复制粘贴 | 复制元件粘贴 | 索引有没有跟着复制 |
| 旋转 | 选中按 `R` | 用了 `LocalToWorld` 就自动对 |
| 导出 PNG | 文件→导出 | ⑨画的和画布不一致 |
| 振荡/悬空 | 输出不驱动 | `FloatV` 语义 |

## 8. 一句话总结

> **定义放 `Document`，元件只存索引，`Pins()` 顺序就是引脚编号，改完必须 `Touch()`，
> 查不到定义一律给安全默认值。**

守住这五条，你的库就能和现有代码完全同构，不用改任何既有元件的代码。

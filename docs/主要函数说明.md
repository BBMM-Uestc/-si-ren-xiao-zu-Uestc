## 一、一张图看懂调用关系

```
                     ┌──────────────────────────────────────────┐
  鼠标/键盘  ───────► │ CanvasPanel::OnLeftDown / OnMotion       │  交互
                     │   ToWorld() 屏幕→世界                     │
                     │   ComputePlacePos() 落点(预览/放置共用)    │
                     │   HitComponent() / HitWire() 命中测试      │
                     └───────────────┬──────────────────────────┘
                                     │ 修改 Document
                                     ▼
        ┌────────────────────────────────────────────────────┐
        │ Document : circuits[] / wires[] / comps[]          │  数据
        │   Size() 外形   Pins() 引脚   Serialize() 存盘     │
        └───────┬──────────────────────────────┬─────────────┘
                │ 只读                          │ 只读
                ▼                              ▼
   ┌────────────────────────┐      ┌────────────────────────────┐
   │ Renderer::DrawComponent│      │ Simulator::Rebuild         │  表现/计算
   │   （画布/图标/PNG 共用）│      │   Flatten 层次展开          │
   │ Renderer::DrawWire     │      │   Settle 迭代收敛           │
   └────────────────────────┘      │   Tick  时钟节拍(两阶段)    │
                                   └────────────────────────────┘
```

**要点**：画布只改 `Document`；渲染和仿真都只**读** `Document`。
所以"改一次数据，画面和仿真同时跟上"，这是整个软件能保持一致的根本原因。

## 五、40 秒口播稿（讲"主要函数"这一页时用）

> "整个软件就靠三个层次串起来：**数据层、表现层、计算层**。
>
> 数据层核心只有两个函数——`Size()` 决定元件多大，`Pins()` 决定引脚在哪。
> 这两个函数一改，绘制、命中测试、仿真接线**全部同步更新**，因为大家读的是同一份数据。
>
> 计算层核心四个函数：`Rebuild()` 把导线归并成网络，`Evaluate()` 算单个元件，
> `Settle()` 迭代到稳定，`Tick()` 推进一个时钟节拍。
> 这里有个关键设计——**Tick 是两阶段的**：先传播组合逻辑，再检测时钟沿锁存，然后再传播一次。
>
> 表现层最值钱的是 `DrawComponent()` 这一个函数：**画布、元件库图标、PNG 导出，三处共用**，
> 所以整个软件没有任何图片资源，视觉效果却到处一致。"

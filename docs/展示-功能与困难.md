## 二、已实现的功能（2 分钟）

> "它不是画图工具——**画出来就能跑**：实时仿真、时钟驱动、层次化、可存盘、可导出。"

### 2.2 分模块清单（每条都配一句"证据"，别只说名词）

| 模块 | 已实现 | 证据 / 怎么看出来 |
|---|---|---|
| **元件库** | 33 种可放置元件，分 6 个库 | 左侧 6 个库按钮上的计数：输入输出 5、门 9、复用器 3、运算 5、存储器 5、布线 6 |
| **渲染** | 全矢量绘制，**零图片资源** | 画布上的元件、元件库里的图标、导出的 PNG，三处是**同一段绘制代码** |

| **分析输出** | 真值表一键生成、PNG 导出、`--export` 无界面批量导出 | 项目菜单→真值表；`MiniLogisim.exe --ticks=13 --export=out.png x.mlc` |
| **工程格式** | UTF-8 纯文本 `.mlc`，可 diff、可脚本生成 | 打开文件用记事本就能看懂 |
| **质量保障** | **36 项断言**的内核自测程序 | 覆盖门真值表、全加器 8 种组合、计数器节拍、分线器位段、隧道、DFF 边沿、子电路、存盘往返 |

### 2.3 三个值得展开讲的技术点（挑 1–2 个讲深）

**① 仿真内核是真的在"解电路"**
> 导线、引脚、隧道先用**并查集**归并成"网络"，再对所有元件**反复求值直到网络稳定**。
> 好处：T 型搭接自动连通、十字交叉自动不连通、组合逻辑环会停下来报"振荡"而不是死循环。

**② 时序元件是边沿触发，不是电平触发**
> 求值阶段只算"下一状态"和"时钟端当前电平"，节拍到来时才检测**上升沿**并锁存。
> 所以计数器的节拍序列是 1、1、2、2、3、3…（每两个节拍加一），这一点在自测里是写死的断言。

**③ 一套渲染代码，三处复用**
> 画布、元件库图标、PNG 导出都调 `Renderer::DrawComponent()`。
> 所以"画布上什么样，库里图标就是什么样，导出的图也是什么样"。

## 三、遇到的困难（2 分钟，这是最容易加分的地方）

> 统一用**四段式**讲：现象 → 排查 → 解法 → 收获。

### 困难 1：仿真"看着在跑，其实根本没动" ★最推荐讲

- **现象**：点开始仿真，界面毫无反应，也不报错。
- **排查**：日志里发现 `wxTimer` 少了 `SetOwner(this)`，定时器**从头到尾没触发过**。
  更坑的是"看不出来"——窗口在后台时 Windows 不重绘，抓到的截图其实是**缓存旧帧**，
  所以现象表现为"像是在跑，但卡住了"。
- **解法**：给程序加了一个 `--export` 无界面导出模式，把"功能对不对"变成
  **"仿真 13 个节拍后计数器是不是 7"**这种可断言的数字。一测就现形。
- **收获**：**GUI 上"看起来正常"不算验证通过**；要把功能做成可断言的输出。

### 困难 2：迭代求值和"边沿触发"天生冲突 ★最能体现技术含量

- **现象**：D 触发器写完就错，输入一变输出立刻跟着变，寄存器变成了"直通"。
- **排查**：组合逻辑是用"反复迭代到稳定"求解的，而迭代天然会把输入立刻传播到输出。
- **解法**：拆成**两阶段**——求值阶段只计算"下一状态 next"和"时钟端电平"，
  节拍到来时才检测上升沿并锁存；同时给迭代设 120 轮上限，超限在状态栏报"检测到振荡"。
- **收获**：组合求解和时序语义**必须分开建模**，不能混在一个循环里。

### 困难 3：连线拓扑——十字交叉不能连、T 型搭接必须连

- **现象**：所有导线都短接在一起，电路完全错。
- **排查**：最初用的是"坐标相同就连通"。
- **解法**：改成只对**"落在别的线段上的点"**做归并。
  十字交叉处**没有任何一条导线的顶点**，所以天然不连通；T 型搭接的端点确实落在别人的线段上，所以连通。
  配合网格哈希索引，把 O(n²) 降到近似 O(n)。
- **收获**：**拓扑判定要基于"顶点"而不是"坐标"**。

### 困难 4：光标位置与实际位置不符 ★最新、观众最容易共鸣

- **现象**：用放置工具点画布，元件出现在离光标很远的地方。
- **排查**：两个原因叠加——
  ① 预览虚影**没有跟随鼠标重绘**，它停在"上次重绘时"的位置，而落点用的是点击瞬间的坐标；
  ② 画布原点跟着"内容包围盒"走，每放一个元件原点就跳一次，屏幕上所有内容整体平移。
- **解法**：预览和落点**合并成同一个函数** `ComputePlacePos()`（从根上不可能再跑偏）；
  原点改成**只向外扩、不向内收**，变化时补偿滚动量；
  再用脚本验证不变量：8428 组组合里**引脚 0 次脱离栅格、中心偏移 ≤5px**。
- **收获**：**两份重复的坐标公式一定会跑偏**，要收敛成一个函数，并把不变量写成可执行的检查。

### 困难 5：查探工具"点了没反应"

- **现象**：点输入引脚毫无反应。
- **排查**：命中判定要求点在**引脚连接点 6px 以内**，点在符号本体上只算"命中元件本体"，于是什么都不做，而且**没有任何提示**。
- **解法**：符号本体可点 + 20px 宽容吸附 + 状态栏回显（`输入 "A" = 1` / `该处电平: 1` / 操作提示）。
- **收获**：**"没反应"必须变成"有反馈"**，哪怕只是一行提示——否则用户无法判断是程序坏了还是点错了。

### 困难 6（一句带过）：中文与构建环境

> MSVC 默认按 GBK 解析源文件，中文全乱码 → 加 `/utf-8` 并全部改用 `wxT()` 宽字面量；
> 本机 wxWidgets **只编译了 Debug 静态库**，Release 直接链接失败，而且库名是 `ud`/`d` 混着的
> （`wxbase32ud.lib`，但 `wxpngd.lib`）。这些都写进 README 了。

### 困难总表（想做成一页幻灯片的话用这个）

| # | 困难 | 根因 | 解法 |
|---|---|---|---|
| 1 | 仿真不推进 | 定时器缺 `SetOwner` | 补上 + 无界面导出断言 |
| 2 | 寄存器变直通 | 迭代求值破坏边沿语义 | 两阶段求解 + 迭代上限 |
| 3 | 导线全短接 | 按坐标判连通 | 并查集 + 只对"点落在线段上"归并 |
| 4 | 元件落点漂移 | 原点随内容漂移 + 预览不刷新 | 单一放置函数 + 原点单调外扩 |
| 5 | 查探无反应 | 命中判定过严且无反馈 | 宽容吸附 + 状态栏回显 |
| 6 | 中文乱码 / 链接失败 | 源编码与库配置 | `/utf-8` + `wxT()`；按实际库名配置 |

## 六、可能被问到

| 提问 | 回答要点 |
|---|---|
| 和 Logisim 有什么区别 | 交互对标，但内核完全自己实现；额外有真值表、PNG/无界面导出；代码量小、结构清晰便于二次开发 |
| 仿真精度 | 理想零延迟、迭代收敛模型；组合环用迭代上限检测并报振荡；**暂不支持传播延迟**（已列为改进项） |
| 怎么保证正确 | `tools/SimTest` 36 项断言，覆盖门真值表、全加器 8 组合、计数器节拍序列、分线器位段、隧道连通、DFF 边沿、子电路层次、存盘往返 |
| 最难的是什么 | 困难 2（迭代求值 vs 边沿触发）——这是仿真器的经典坑 |
| 有什么没做完 | 运行时动态元件库：模型/绘制/仿真/序列化已写好，但界面入口还没接线；另有传播延迟、增量重建网络 |
